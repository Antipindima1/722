# Перегенерация OpenAPI и Sequence по навыкам

- **Дата:** 2026-11-22
- **Навыки:** `skills/openapi-design` (правила E-09, E-10), `skills/sequence-diagram` (правило E-09)
- **Источники:** `SCRUM-2189`, `SCRUM-2190`, `knowledge/02-business-rules.md`,
  `knowledge/03-assumptions.md`
- **Результат:** ошибки найдены проверкой, правило добавлено в навык, повторная проверка чистая

## Порядок цикла

1. Сгенерированы заново: спецификация и диаграмма — без копирования прошлых версий.
2. Первый прогон Spectral **упал**: `parser: Incomplete explicit mapping pair`, строка 156.
3. Причина: в `description` стояло `Сводка: принято…` — двоеточие с пробелом внутри значения.
4. В навык `openapi-design` добавлено правило E-10: значения с `: ` — в кавычках.
5. Значение исправлено, повторный прогон чистый.
6. Диаграмма отрисована и проверена по содержимому.

| Проверка | Команда | Результат |
|---|---|---|
| OpenAPI, первый прогон | `spectral lint … --format json` | **ошибка парсера**, 1 проблема |
| OpenAPI, повторный прогон | то же | код 0, ошибок 0, файл `[]` |
| Рендер Sequence | `POST https://kroki.io/plantuml/svg` | HTTP 200, 49 599 байт |
| Содержимое диаграммы | поиск по тексту SVG | 8 из 8: сервис выплат, `payouts/exists:batch`, `ALREADY_PAID`, `VALIDATION_FAILED`, `BLOCKED`, DLQ, `304 Not Modified`, `REGISTRY_LIMIT_EXCEEDED` |

## Что дало правило E-09

| Проверка | Источник данных в новой генерации |
|---|---|
| `CHK-01`, `CHK-02` | файл реестра, лимиты проверяются на приёме |
| `CHK-03…CHK-06` | строки файла, справочник исполнителей |
| `CHK-07` | внутренняя операция `POST /payouts/exists:batch` сервиса выплат (пакет до 500 строк) |

В диаграмме это шаги 21–23: сервис реестров обращается к сервису выплат и отклоняет строку
с причиной `ALREADY_PAID`. Источник данных показан явно, а не подразумевается.

## Сравнение с предыдущей версией

| Что было | В новой генерации |
|---|---|
| Ссылка на проверку «уже выплачено» без источника | операция `payouts/exists:batch` и шаги 21–23 |
| В описании загрузки только лимит строк | все три лимита и код `REGISTRY_LIMIT_EXCEEDED` |
| YAML без правил цитирования | правило E-10, проверка парсером до любых других |

## Ограничения

- Sequence проверена рендером и поиском по тексту; ручная сверка каждого шага с бизнес-логикой
  не выполнялась — это делает ревью.
- OpenAPI проверен Spectral; поведение за контрактом не проверялось, реализации нет.

## Вывод

Обе ошибки, найденные при генерации, зафиксированы и закрыты правилами навыков:
E-09 — проверка без источника данных не описывается, E-10 — значения с двоеточием в кавычках.
Повторные прогоны чистые.
