# OpenAPI — реестр выплат (Ф1)

- **Артефакт:** `artifacts/openapi-registry.yaml` (OpenAPI 3.0.3)
- **Фича:** Ф1 «Загрузка и проверка реестра выплат» — `SCRUM-2187`, истории `SCRUM-2189`, `SCRUM-2190`
- **Инструмент проверки:** Spectral, правила `spectral:oas` + дополнения (`.spectral.yaml`)
- **Дата:** 2026-11-17

## Границы

В спецификации только контур реестра: загрузка файла, статус, строки с причинами отказа,
отчёт по проверке. Выплаты по СБП (Ф2) и чеки ФНС сюда не входят.

## Принятые решения

| Решение | Почему так | Источник |
|---|---|---|
| Загрузка асинхронная: `202 Accepted` + опрос статуса | проверка 5 000 строк не должна держать HTTP-соединение; результат нужен позже | `AS-02`, `CHK-01` |
| `Idempotency-Key` обязателен на `POST /registries` | повторная загрузка того же файла не должна создавать второй реестр | `AS-13` |
| Статусы реестра: `UPLOADED/VALIDATING/CHECKED/BLOCKED/VALIDATION_FAILED/REJECTED/CANCELLED/PAYING/DONE/DONE_WITH_ERRORS` | совпадают с жизненным циклом в базе знаний, включая этап выплаты | `02-business-rules.md` §4.1 |
| Статусы строки `NEW/VALIDATED/REJECTED/PAYING/PAID/FAILED` и коды причин | бухгалтер исправляет только ошибочные строки, причина машиночитаема; статусы выплаты учтены | `CHK-03…CHK-07`, `SCRUM-2190` |
| Пагинация `limit/offset` + `total` | реестр до 5 000 строк, отдавать целиком нельзя | `AS-02` |
| `ETag` + `If-None-Match` на статус реестра | бухгалтер опрашивает статус часто, 304 экономит трафик | решение, `AS-18` |
| Маскирование ИНН и ФИО в списках | персональные данные не должны уходить в общий список | `O-06`, `AS-15` |
| Ответы об ошибках с кодом и сообщением | без кода клиент не отличит формат файла от конфликта статуса | `AS-01` |
| Лимиты в спецификации: 5 000 строк, 10 000 000 ₽ на реестр, 1 000 000 ₽ на строку | лимиты из `AS-02` должны быть видны клиенту в контракте, а не только в коде | `AS-02`, `CHK-05` |
| Суммы — строка с двумя знаками после точки | `format: decimal` не входит в OpenAPI и неоднозначен для генераторов | решение, `S-03` ревью |
| Статус `VALIDATION_FAILED` отдельно от `BLOCKED` | технический сбой нельзя смешивать с блокировкой по качеству данных: бухгалтеру при сбое хранилища нечего исправлять в файле | `AS-19`, `AS-14` |
| Операция `POST /registries/{registryId}/revalidation` | повторная проверка нужна после сбоя и доступна только из `VALIDATION_FAILED`; из `BLOCKED` — только новая загрузка | `AS-19` |

## Коды ответов

| Код | Когда |
|---|---|
| `202` | файл принят, проверка выполняется |
| `200` | статус, строки, отчёт |
| `304` | статус не изменился (`If-None-Match`) |
| `400` | файл или параметры некорректны (формат, отсутствуют обязательные колонки) |
| `401` | нет аутентификации |
| `403` | нет прав на операцию |
| `404` | реестр не найден или принадлежит другой компании |
| `409` | конфликт: превышен лимит реестра, реестр заблокирован, повтор с другим телом при том же `Idempotency-Key` |
| `413` | файл превышает допустимый размер |

## Коды ошибок

Машиночитаемые коды лежат в схеме `ErrorCode`; клиент различает ситуации по `code`, а не по
тексту `message`.

Правило для 5xx: серверные ошибки не означают, что операция не выполнена. Клиент повторяет
запрос с тем же `Idempotency-Key` (загрузка идемпотентна), а для чтения — просто повторяет.
`Retry-After` в ответе `503` задаёт паузу.

| Код | HTTP | Когда | Что делать клиенту |
|---|---|---|---|
| `FORMAT_INVALID` | 400 | файл не CSV/XLSX или не читается | исправить формат и загрузить заново |
| `MISSING_REQUIRED_COLUMNS` | 400 | нет обязательной колонки (`AS-01`) | добавить колонки, загрузить заново |
| `INVALID_QUERY_PARAM` | 400 | некорректный `status`, `limit`, `offset` или размер пачки больше 500 | исправить параметры запроса |
| `UNAUTHENTICATED` | 401 | нет или истёк токен | получить новый токен |
| `FORBIDDEN` | 403 | нет прав на операцию | обратиться к администратору компании |
| `REGISTRY_NOT_FOUND` | 404 | реестр не найден или чужая компания | проверить идентификатор |
| `REGISTRY_LIMIT_EXCEEDED` | 409 | превышены лимиты строк или суммы (`AS-02`) | разбить реестр на части |
| `REGISTRY_BLOCKED` | 409 | реестр заблокирован из-за доли ошибок (`AS-14`) | исправить файл и загрузить новый реестр |
| `REGISTRY_NOT_VALIDATION_FAILED` | 409 | повторная проверка запрошена для реестра не из `VALIDATION_FAILED` | проверить статус реестра |
| `IDEMPOTENCY_KEY_REUSED` | 409 | тот же `Idempotency-Key`, но другой файл | использовать новый ключ для нового файла |
| `FILE_TOO_LARGE` | 413 | файл больше допустимого размера | уменьшить файл или разбить реестр |
| `INTERNAL_ERROR` | 500 | непредвиденная ошибка на стороне сервиса | повторить запрос; для `POST` — с тем же `Idempotency-Key` |
| `SERVICE_UNAVAILABLE` | 503 | сервис или зависимость временно недоступны | подождать `Retry-After` и повторить; загрузка идемпотентна |
| `UPSTREAM_TIMEOUT` | 503 | не ответила зависимость (хранилище, сервис выплат) | повторить запрос позже; статус реестра проверить опросом |

## Трассировка к критериям приёмки

| Критерий | Где в спецификации |
|---|---|
| Приём CSV/XLSX с обязательными колонками | `POST /registries`, `multipart/form-data`, поле `file` |
| Лимиты реестра | `409` + описание лимитов в `POST /registries` |
| Статусы «Загружен» → «Проверяется» | `RegistryStatus`, `RegistryAccepted` |
| Отчёт по каждой строке с причиной | `GET /registries/{registryId}/rows`, `rejectReason`, `rejectMessage` |
| Блокировка при превышении доли ошибок | `GET /registries/{registryId}/report`, поле `blocked` |
| Список реестров с фильтром | `GET /registries`, параметр `status` |

## Открытые вопросы

| Вопрос | Почему открыт |
|---|---|
| Нужен ли `GET /registries/{id}/rows/{rowId}` с полными данными | маскирование в списке есть, доступ к полным данным не описан в требованиях |
| Формат скачивания отчёта (JSON или файл) | требования говорят «отчёт доступен», формат не задан |
| Срок хранения загруженных файлов | `AS-11` задаёт 12 месяцев для фото, для реестров срок не определён |
