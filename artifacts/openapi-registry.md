# OpenAPI — реестр выплат (Ф1)

- **Артефакт:** `artifacts/openapi-registry.yaml` (OpenAPI 3.0.3)
- **Фича:** Ф1 «Загрузка и проверка реестра выплат» — `SCRUM-2187`, истории `SCRUM-2189`, `SCRUM-2190`
- **Инструмент проверки:** Spectral, правила `spectral:oas` + дополнения (`.spectral.yaml`)
- **Дата:** 2026-11-17

## Границы

В спецификации только контур реестра: загрузка файла, статус, строки с причинами отказа,
отчёт по проверке. Выплаты по СБП (Ф2) и чеки ФНС сюда не входят.

## Принятые решения

| Решение | Почему так | Источник |
|---|---|---|
| Загрузка асинхронная: `202 Accepted` + опрос статуса | проверка 5 000 строк не должна держать HTTP-соединение; результат нужен позже | `AS-02`, `CHK-01` |
| `Idempotency-Key` обязателен на `POST /registries` | повторная загрузка того же файла не должна создавать второй реестр | `AS-13` |
| Статусы реестра `UPLOADED/VALIDATING/CHECKED/BLOCKED/REJECTED/CANCELLED` | совпадают с жизненным циклом в базе знаний | `02-business-rules.md` §4.1 |
| Статусы строки `NEW/VALIDATED/REJECTED` и коды причин | бухгалтер исправляет только ошибочные строки, причина машиночитаема | `CHK-03…CHK-07`, `SCRUM-2190` |
| Пагинация `limit/offset` + `total` | реестр до 5 000 строк, отдавать целиком нельзя | `AS-02` |
| `ETag` + `If-None-Match` на статус реестра | бухгалтер опрашивает статус часто, 304 экономит трафик | решение, `AS-18` |
| Маскирование ИНН и ФИО в списках | персональные данные не должны уходить в общий список | `O-06`, `AS-15` |
| Ответы об ошибках с кодом и сообщением | без кода клиент не отличит формат файла от конфликта статуса | `AS-01` |
| Внутренняя операция `GET /payouts/exists` | проверка «не выплачен ранее» требует данных выплат; обращаемся к сервису-владельцу, а не читаем чужую БД | `CHK-07`, `AS-13` |
| Суммы — строка с двумя знаками после точки | `format: decimal` не входит в OpenAPI и неоднозначен для генераторов | решение, `S-03` ревью |

## Коды ответов

| Код | Когда |
|---|---|
| `202` | файл принят, проверка выполняется |
| `200` | статус, строки, отчёт |
| `304` | статус не изменился (`If-None-Match`) |
| `400` | файл или параметры некорректны (формат, отсутствуют обязательные колонки) |
| `401` | нет аутентификации |
| `403` | нет прав на операцию |
| `404` | реестр не найден или принадлежит другой компании |
| `409` | конфликт: превышен лимит реестра, реестр заблокирован, повтор с другим телом при том же `Idempotency-Key` |
| `413` | файл превышает допустимый размер |

## Трассировка к критериям приёмки

| Критерий | Где в спецификации |
|---|---|
| Приём CSV/XLSX с обязательными колонками | `POST /registries`, `multipart/form-data`, поле `file` |
| Лимиты реестра | `409` + описание лимитов в `POST /registries` |
| Статусы «Загружен» → «Проверяется» | `RegistryStatus`, `RegistryAccepted` |
| Отчёт по каждой строке с причиной | `GET /registries/{registryId}/rows`, `rejectReason`, `rejectMessage` |
| Блокировка при превышении доли ошибок | `GET /registries/{registryId}/report`, поле `blocked` |
| Список реестров с фильтром | `GET /registries`, параметр `status` |
| Проверка «не выплачен ранее» (`CHK-07`) | `GET /payouts/exists` + причина `ALREADY_PAID` в строке |

## Открытые вопросы

| Вопрос | Почему открыт |
|---|---|
| Нужен ли `GET /registries/{id}/rows/{rowId}` с полными данными | маскирование в списке есть, доступ к полным данным не описан в требованиях |
| Формат скачивания отчёта (JSON или файл) | требования говорят «отчёт доступен», формат не задан |
| Срок хранения загруженных файлов | `AS-11` задаёт 12 месяцев для фото, для реестров срок не определён |
