# Артефакты

Одна папка — одна фича. Название папки совпадает с названием фичи в Jira и в `knowledge/features`.

```
artifacts/
├── c4/                          системная архитектура (не привязана к одной фиче)
├── feature-registry-check/      Ф1. Загрузка и проверка реестра (SCRUM-2187)
├── feature-sbp-payout/          Ф2. Выплата по СБП (SCRUM-2188)
├── dbeaver-check.md             проверка DDL в DBeaver (сквозная)
├── dbeaver-schema-verify.png    скриншот прогона
├── rule-run.md                  прогон правил по всем артефактам
└── verification-matrix.md       матрица «артефакт → инструмент проверки»
```

## Что лежит в папке фичи

| Файл | Назначение |
|---|---|
| `<артефакт>.yaml` / `.md` / `.puml` | сам артефакт в исходном виде |
| `<артефакт>.svg` | рендер диаграммы для чтения и ревью |
| `<артефакт>-check.md` | отчёт проверки: самопроверка, команда, вывод, ограничения |
| `<артефакт>-review.md`, `-review-v2.md` | ревью и повторная проверка |
| `schema-*.sql` | DDL и вспомогательные скрипты (сброс, самопроверка) |
| `*.agent-draft.*` | перегенерация артефакта по навыку (доказательство цикла) |

## Правило пополнения

Новый артефакт кладётся в папку своей фичи, а не в корень `artifacts`. Сквозные отчёты
(проверка инструментом по всем артефактам, матрица проверок) остаются в корне.
