## 🟡 Стоит улучшить

### S-01. Политика повторов описана текстом, но не в спецификации

- **Где:** `asyncapi-registry.yaml`, канал `registry.events.dlq`; `asyncapi-registry.md`,
  раздел «Надёжность».
- **Что не так:** «3 попытки 1 / 5 / 15 секунд» есть в markdown, но в самой спецификации
  этого нет — ни через `bindings`, ни через расширения.
- **Почему важно:** спецификация — единственный источник для реализации; политику,
  описанную рядом, легко не заметить при генерации кода.
- **Как исправить:** добавить `x-retry-policy` на уровне канала или операции с полями
  `maxAttempts`, `backoffSeconds`, `dlqChannel`.
- **Серьёзность:** 🟡.

### S-02. `DlqEnvelope.originalEvent` — объект без схемы

- **Где:** `asyncapi-registry.yaml`, `components.schemas.DlqEnvelopePayload.originalEvent`.
- **Что не так:** тип `object` без структуры; читатель не знает, что именно лежит внутри.
- **Почему важно:** DLQ разбирают вручную, а без схемы нельзя проверить, что сообщение
  сохранено полностью.
- **Как исправить:** `oneOf` из трёх payload-схем (`RegistryUploadedPayload`,
  `RegistryCheckedPayload`, `RegistryValidationFailedPayload`).
- **Серьёзность:** 🟡.

### S-03. `RegistryUploadedPayload.status` допускает `UPLOADED`, хотя событие публикуется после перехода в `VALIDATING`

- **Где:** `asyncapi-registry.yaml`, `RegistryUploadedPayload.properties.status`.
- **Что не так:** по Sequence шаг 6 переводит реестр в `VALIDATING`, шаг 7 публикует событие.
  Значит в событии всегда `VALIDATING`; значение `UPLOADED` в enum вводит в заблуждение.
- **Почему важно:** клиент начнёт писать обработку для состояния, которое не приходит.
- **Как исправить:** оставить в enum только `VALIDATING` либо публиковать событие до смены
  статуса и тогда убрать `VALIDATING`.
- **Серьёзность:** 🟡.

### S-04. Нет канала для повторной проверки реестра

- **Где:** спецификация целиком.
- **Что не так:** по `AS-14` заблокированный реестр исправляют и загружают заново — это новый
  реестр, но повторная проверка того же реестра (например, после устранения сбоя хранилища)
  событием не описана.
- **Почему важно:** ветку «файл недоступен» на Sequence можно закрыть только повторной
  проверкой; сейчас в спецификации для неё нет сообщения.
- **Как исправить:** либо добавить канал `registry.revalidation-requested`, либо явно
  записать в открытых вопросах, что повторная проверка не поддерживается и реестр
  загружается заново.
- **Серьёзность:** 🟡.
