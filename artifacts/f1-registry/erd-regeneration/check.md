# Перегенерация ERD/DDL после правки навыка

- **Дата:** 2026-11-22
- **Навык:** `skills/erd-data-model/SKILL.md`, раздел «Правила из журнала ошибок» (E-08)
- **Источник требований:** `SCRUM-2189`, `SCRUM-2190`, `knowledge/02-business-rules.md`,
  `knowledge/03-assumptions.md`
- **Результат:** ошибки не повторились, проверка чистая

## Что сделано

1. Навык `erd-data-model` дополнен правилом E-08: «каждый лимит и каждая проверка из критериев
   приёмки отражены в схеме либо явно вынесены в допущения».
2. DDL сгенерирован **заново** по критериям приёмки и `knowledge`, без копирования предыдущей
   версии: `artifacts/erd-regeneration/agent-draft.sql`.
3. Драфт проверен тем же способом, что и раньше: исполнение на PGlite + негативные вставки.
4. Результат записан в `ai-log.md` (запись E-08, раздел «Перегенерация»).

## Что проверялось

| Требование | Как отражено в новой генерации |
|---|---|
| ИНН: длина **и контрольная сумма** (`AS-09`) | функция `inn_is_valid()` + CHECK на `contractors.inn` и `payout_rows.inn` |
| Реестр до 10 000 000 ₽ (`AS-02`) | CHECK `total_amount <= 10000000` |
| Строка до 1 000 000 ₽ (`AS-02`) | CHECK `amount <= 1000000` |
| До 5 000 строк (`AS-02`) | CHECK `row_count BETWEEN 0 AND 5000` |
| Отчёт сохраняется с реестром (`SCRUM-2190`) | таблица `validation_reports` с PK `registry_id` |
| Статусы полного цикла (`§4.1–4.4`) | 10 значений реестра, 6 строки, 4 выплаты, 4 чека |
| Идемпотентность загрузки (`AS-13`) | уникальный `idempotency_key` |
| Повторная выплата невозможна (`CHK-07`) | уникальный `payouts.row_id` |
| Повторная обработка событий (`AS-13`) | таблица `processed_events` |
| Дубли ИНН в реестре (`O-08`) | частичный уникальный индекс по принятым строкам |

## Сравнение с первой генерацией

| Ошибка первой версии | В новой генерации |
|---|---|
| Проверялся только формат ИНН, без контрольной суммы | контрольная сумма есть, вставка `123456789012` отбита |
| Не было лимита суммы реестра | CHECK на 10 000 000 ₽, вставка 10 000 001 ₽ отбита |
| Не было таблицы сохранённого отчёта | `validation_reports`, повторный отчёт отбит |
| Статусы покрывали только этап проверки | полный цикл: `PAYING`, `DONE`, `DONE_WITH_ERRORS`, `PAID`, `FAILED` |

## Ограничения проверки

- Прогон на PGlite (PostgreSQL 18.6 в WASM): типы, ограничения и индексы проверяются честно,
  поведение под конкуренцией — нет.
- Полный прогон в DBeaver выполнен отдельно для основной схемы
  (`artifacts/dbeaver-check.md`); для драфта достаточно автоматического прогона.
