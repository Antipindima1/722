## 9. Правка по замечанию о протоколах

Замечание: связь `Сервис выплат` → `Адаптер ФНС` была без протокола — на диаграмме
единственная связь без технологии.

Разбор: контракт внешней системы не задан (`AS-16`), но эта связь **внутренняя** — её
протокол является нашим архитектурным решением (`AS-18`), а не внешним контрактом,
поэтому пустой она быть не должна.

Что исправлено:

- связь `Сервис выплат` → `Адаптер ФНС` получила протокол `REST/JSON`;
- связь `Адаптер ФНС` → `ФНС «Мой налог»` помечена `HTTPS, контракт не задан` — здесь
  неопределённость честно названа, а не скрыта;
- добавлена **таблица взаимодействий** (`from / to / назначение / протокол / источник`),
  которой требует формат результата навыка; в ней 15 связей и у каждой указан протокол
  или явная пометка «контракт не задан».

## 10. Автопроверка протоколов связей

Причина появления: замечание по связи `Сервис выплат → Адаптер ФНС`, у которой не был
указан протокол. Чтобы такое не проходило на глазок, добавлена машинная проверка:
каждая связь `Rel(...)` должна иметь четвёртый аргумент (протокол/технологию), либо явную
пометку «контракт не задан».

Проверка:

```python
import io, re

text = io.open("artifacts/c4-container.puml", encoding="utf-8").read()
rels = re.findall(r"^Rel\((.*)\)\s*$", text, re.M)


def args(s):
    out, cur, q = [], "", False
    for ch in s:
        if ch == '"':
            q = not q
            cur += ch
            continue
        if ch == "," and not q:
            out.append(cur.strip())
            cur = ""
            continue
        cur += ch
    out.append(cur.strip())
    return out


missing = [r for r in rels if len(args(r)) < 4 or not args(r)[3].strip()]
print("Rel всего:", len(rels))
print("без протокола:", len(missing))
for m in missing:
    print("  MISSING", args(m)[0], "->", args(m)[1])
```

Результат прогона:

| Параметр | Значение |
|---|---|
| Связей `Rel` | 15 |
| С протоколом | 15 |
| Без протокола | **0** |

Критерий приёмки: `без протокола = 0`. Если значение больше нуля, артефакт не готов —
надо либо указать протокол, либо явно написать «контракт не задан» со ссылкой на `AS-16`.

## 11. Требования в контейнерах — словами, без внутренних ID

Причина: в описаниях контейнеров стояли ссылки на внутренние идентификаторы правил
(`CHK-01…CHK-07`, `CHK-08…CHK-12`). Человек, который смотрит только диаграмму, из этого
ничего не узнаёт: чтобы понять ответственность контейнера, ему нужна база знаний.

Правило: **описание контейнера формулируется требованием на человеческом языке**, а
номера правил остаются в таблицах трассировки артефакта (§5) и в базе знаний. Диаграмма
должна читаться без обращения к внутренним документам.

Что переписано:

| Контейнер | Было | Стало |
|---|---|---|
| Сервис реестров | «Приём файла, проверки `CHK-01…CHK-07`, статусы реестра и строк» | «Приём файла реестра, проверка формата, обязательных полей, ИНН, дублей, сумм и телефонов; статусы реестра и строк» |
| Сервис выплат | «Проверки `CHK-08…CHK-12`, отправка в СБП, идемпотентность, ретраи» | «Проверка статуса самозанятого, средств и лимитов; переводы через СБП, защита от повторных списаний, повторные попытки» |
| Очередь событий | «События реестра и выплат, `DLQ`» | «События реестра и выплат, недоставленные сообщения для разбора» |

Автопроверка: в блоке диаграммы не должно быть вхождений `CHK-`, `AS-`, `O-`, `SCRUM-`.

```python
import io, re
text = io.open("artifacts/c4-container.md", encoding="utf-8").read()
puml = re.search(r"```plantuml\s*\n(.*?)```", text, re.S).group(1)
hits = re.findall(r"(?:CHK-\d+|AS-\d+|O-\d+|SCRUM-\d+)", puml)
print("внутренних ID в диаграмме:", len(hits), hits)
```

Результат:

| Параметр | Значение |
|---|---|
| Внутренних ID в диаграмме | **0** |
| Требования словами найдены в SVG | 5 из 5 |
| HTTP | 200 |
| Размер SVG | 42 570 байт |
| Canvas | 1551×1404 px |

Критерий приёмки: `внутренних ID в диаграмме = 0`. Номера правил допустимы только в
текстовых таблицах трассировки, где у них есть расшифровка.
