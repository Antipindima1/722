## 🔴 Критичное (требует исправления)

### S-01. Повторная отправка в СБП без ключа идемпотентности

- **Где:** `sequence-payout.md`, шаг 23 «повтор POST /payments».
- **Что не так:** первая отправка (шаг 18) идёт с `Idempotency-Key`, а повтор — без него.
- **Почему важно:** если СБП выполнил перевод, но ответ потерялся, повтор без того же ключа
  создаст второй перевод. Это прямое нарушение `AS-13` и `CHK-11`.
- **Как исправить:** повтор использовать с тем же `Idempotency-Key`, что и первая попытка
  (ключ выплаты), и указать это на шаге.
- **Серьёзность:** 🔴.

## 🟡 Стоит улучшить

### S-02. Ошибка в отчёте: число предупреждений AsyncAPI

- **Где:** `check.md`, раздел AsyncAPI.
- **Что не так:** указано «5 предупреждений», фактически 6 (лицензия, email и четыре `messageId`).
- **Почему важно:** отчёт проверки должен совпадать с выводом инструмента, иначе доверие к нему падает.
- **Как исправить:** привести число к 6 и перечислить их.
- **Серьёзность:** 🟡.

### S-03. Нет перехода реестра в «В выплате»

- **Где:** `sequence-payout.md`, шаги 10 и 28.
- **Что не так:** после создания выплат реестр остаётся в `CHECKED` и сразу переходит в `DONE`.
  В §4.1 базы знаний есть промежуточный статус «В выплате» (`PAYING`).
- **Почему важно:** статус реестра — то, что видит бухгалтер; без него экран показывает
  «Проверен», пока идут выплаты.
- **Как исправить:** добавить `UPDATE registry (status=PAYING)` перед обработкой строк.
- **Серьёзность:** 🟡.

### S-04. Не показан отказ СБП по бизнес-причине

- **Где:** `sequence-payout.md`, ветки шага 19.
- **Что не так:** есть только «Техническая ошибка» и «Статус утрачен»; статус `DECLINED`
  используется лишь для `CONTRACTOR_STATUS_LOST`. Отказ СБП (например, счёт получателя закрыт)
  не отражён.
- **Почему важно:** это штатный бизнес-исход, а не техническая ошибка; повторять его бессмысленно.
- **Как исправить:** добавить ветку «СБП отклонил перевод» → `DECLINED` с причиной, без ретраев.
- **Серьёзность:** 🟡.

### S-05. Источник данных для суточного лимита указан неполно

- **Где:** `sequence-payout.md`, шаг 8 «SELECT sum(amount) за сутки».
- **Что не так:** не сказано, по чему считается сумма — нужны выплаты компании за сутки,
  то есть соединение `payouts` с `registries.company_id`.
- **Почему важно:** правило E-09 требует явного источника данных; без компании лимит считается неверно.
- **Как исправить:** уточнить запрос: сумма выплат компании за сутки.
- **Серьёзность:** 🟡.

### S-06. Нет ветки «ФНС недоступна»

- **Где:** `sequence-payout.md`, шаги 14–15.
- **Что не так:** запрос статуса самозанятого предполагает ответ; таймаут не описан.
- **Почему важно:** `AS-17` задаёт ретраи для технических ошибок; неясно, блокируется ли выплата.
- **Как исправить:** добавить ветку «ФНС не ответила» → повтор, затем `ERROR`/DLQ.
- **Серьёзность:** 🟡.
