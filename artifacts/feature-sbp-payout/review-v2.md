## 🟡 Стоит улучшить

### S-07. Причина `FNS_UNAVAILABLE` не объявлена в схеме события

- **Где:** `asyncapi-payouts.yaml`, `PayoutFailedPayload.reason` — enum
  `[SBP_REJECTED, SBP_TIMEOUT, CONTRACTOR_STATUS_LOST, INTERNAL_ERROR]`;
  `sequence-payout.md`, шаг 17 использует `reason=FNS_UNAVAILABLE`.
- **Что не так:** значение есть в сценарии, но отсутствует в схеме события. Потребитель,
  построивший клиент по схеме, не обработает такой отказ.
- **Почему важно:** нарушение `R-07` — одно значение должно называться одинаково во всех
  артефактах.
- **Как исправить:** добавить `FNS_UNAVAILABLE` в enum `PayoutFailedPayload.reason`.
- **Серьёзность:** 🟡.

### S-08. Бизнес-отказ СБП не порождает событие

- **Где:** `sequence-payout.md`, шаги 28–29; `asyncapi-payouts.yaml` — события `PayoutSent`,
  `PayoutFailed`, `PayoutRetryScheduled`.
- **Что не так:** при отказе СБП по бизнес-причине выплата становится `DECLINED`, но событие
  не публикуется: `PayoutFailed` по `AS-21` означает «после исчерпания попыток», а это другой случай.
- **Почему важно:** сервис уведомлений и отчёт не узнают о штатном отказе, пока бухгалтер
  не откроет экран.
- **Как исправить:** либо публиковать `PayoutFailed` и для `DECLINED` (уточнив смысл в `AS-21`),
  либо добавить отдельное событие `PayoutDeclined`. Решение — за автором, но зафиксировать нужно.
- **Серьёзность:** 🟡.
