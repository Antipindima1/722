## Замечания

### S-01. В базе знаний устаревшее утверждение о неназначенном типе артефакта

- **Где:** `knowledge/04-task-SA-2378.md`, раздел «Таблица выбора артефакта», строка
  «Статус выбора».
- **Что не так:** написано «тип артефакта ментором пока не назначен — в Jira `SA-2378` нет
  ни комментария с назначением, ни поля „Ссылка на решение“». Фактически ментор назначил
  **все четыре** типа артефактов, и в репозитории уже стоят навыки под каждый из них.
- **Почему это ошибка:** документ противоречит фактическому составу `skills/` (шесть
  навыков вместо нуля) и вводит агента в заблуждение: по `AGENTS.md` §3 он обязан
  остановиться и спросить, хотя решение уже принято. Назначение при этом нигде не
  зафиксировано в источнике фактов — в Jira `SA-2378` по-прежнему 0 комментариев,
  обновление от 12.11.
- **Как исправить:** убрать утверждение «не назначен», записать «назначены все четыре
  артефакта из таблицы» и, чтобы это стало фактом, а не пересказом, — добавить комментарий
  в `SA-2378` с назначением (поле «Ссылка на решение» можно оставить пустым до сдачи PR).
  Без записи в Jira статус остаётся допущением.
- **Серьёзность:** существенное.

### S-02. `AGENTS.md` §5 не упоминает постановку задачи

- **Где:** `AGENTS.md`, §5 «Работа с базой знаний knowledge», список основных документов.
- **Что не так:** перечислены `README.md`, `01-glossary.md`, `02-business-rules.md`,
  `03-assumptions.md`, `entities/` — файла `04-task-SA-2378.md` в списке нет.
- **Почему это ошибка:** по §5 агент получает перечень обязательных документов базы
  знаний и не увидит постановку задачи с таблицей артефактов и Definition of Done —
  то есть пропустит требования, по которым его же работу принимают (`SA-2378`).
- **Как исправить:** добавить строку
  «`knowledge/04-task-SA-2378.md` — постановка задачи, порядок работ и Definition of Done».
- **Серьёзность:** существенное.

### S-03. Дерево репозитория в `AGENTS.md` §6 не совпадает с фактическим

- **Где:** `AGENTS.md`, §6, блок ```text``` со структурой.
- **Что не так:** в схеме есть `docs/`, `src/`, `tests/`, но нет `skills/`, нет
  `knowledge/04-task-SA-2378.md`, нет `artifacts/`; при этом §9 требует открывать
  `skills/README.md`, а §7 — класть отчёты в `artifacts/`.
- **Почему это ошибка:** документ описывает структуру, которой нет, и молчит о той, что
  есть. Агент, следуя §6, будет искать навыки и постановку задачи в неверных местах.
  Сам §6 требует «проверяй фактическую структуру репозитория», но собственный пример
  ей противоречит.
- **Как исправить:** привести схему к факту — оставить `knowledge/`, добавить `skills/`
  с подпапками навыков и `artifacts/`, пометить `docs/`, `src/`, `tests/` как «планируются».
- **Серьёзность:** существенное.

### S-04. Корневой `README.md` описывает репозиторий без навыков и правил агента

- **Где:** `README.md`, раздел «Структура».
- **Что не так:** таблица содержит только файлы `knowledge/*`, тогда как в репозитории
  есть `AGENTS.md`, `skills/` (6 навыков) и `knowledge/04-task-SA-2378.md`.
- **Почему это ошибка:** README — точка входа для человека и агента; по нему невозможно
  узнать, что в репозитории есть правила работы и навыки, то есть половина назначения
  репозитория (`SA-2378`: «в нём есть knowledge, AGENTS.md, skills/<название>/SKILL.md,
  artifacts и ai-log.md») не видна.
- **Как исправить:** добавить в таблицу `AGENTS.md`, `skills/` (с каталогом и шестью
  навыками), `knowledge/04-task-SA-2378.md`; строку про `artifacts/` и `ai-log.md`
  пометить как «появятся при выполнении SA-2378».
- **Серьёзность:** существенное.

### S-05. Битая wikilink `[[AGENTS]]` в постановке задачи

- **Где:** `knowledge/04-task-SA-2378.md`, раздел «Связи».
- **Что не так:** ссылка `[[AGENTS]]` не разрешается: в vault `knowledge/` заметки с таким
  именем нет, `AGENTS.md` лежит в корне репозитория, вне vault.
- **Почему это ошибка:** в Obsidian ссылка откроет пустую заметку и создаст мусорный
  файл `AGENTS.md` внутри `knowledge/`; переход к правилам агента не работает
  (`knowledge/README.md`, правило 3 «связи через `[[wikilink]]`»).
- **Как исправить:** заменить на обычный markdown-путь `../AGENTS.md` (или на текст
  в code-span `AGENTS.md`), не создавая заметку-дубль.
- **Серьёзность:** пожелание.

### S-06. Каталог навыков использует wikilinks вне Obsidian-vault

- **Где:** `skills/README.md`, таблица «Каталог».
- **Что не так:** ссылки вида `[[c4-container-diagram/SKILL|c4-container-diagram]]`.
- **Почему это ошибка:** vault — это папка `knowledge/`; `skills/` в неё не входит, значит
  в Obsidian эти ссылки не разрешаются и ведут в пустоту.
- **Как исправить:** либо заменить на относительные markdown-ссылки
  (`c4-container-diagram/SKILL.md`), либо открывать vault из корня репозитория, если это
  удобнее — но тогда изменится область vault и настройки `.obsidian/`.
- **Серьёзность:** пожелание.
