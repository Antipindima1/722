# Ф1. Загрузка и проверка реестра выплат

## Цель

Дать бухгалтеру загрузить реестр и до выплаты увидеть все проблемные строки, чтобы не
платить по ошибочным данным. Источник фичи: `Описание продукта` («фичи на выбор»).

## Пользователь

Бухгалтер компании. Источник: `Описание продукта`.

## Сценарий

1. Бухгалтер загружает файл реестра.
2. Система проверяет формат и обязательные поля (`CHK-01`, `CHK-02`).
3. По каждой строке: ИНН (`CHK-03`), дубли (`CHK-04`), сумма (`CHK-05`), телефон (`CHK-06`),
   отсутствие предыдущей выплаты (`CHK-07`).
4. Формируется отчёт: принято / отклонено, с причиной по каждой строке.
5. Реестр переходит в «Проверен» либо «Заблокирован», если ошибок больше порога (`AS-14`).

## Результат

Реестр в статусе «Проверен» с валидными строками, готовыми к выплате, и отчёт об ошибках.

## Применимые правила

`O-03`, `O-07`, `O-08`; статусы [[02-business-rules#4.1. Реестр выплат]] и
[[02-business-rules#4.2. Строка реестра]]; допущения `AS-01`, `AS-02`, `AS-04`, `AS-09`,
`AS-10`, `AS-14`.

## Критерии приёмки (для проверки артефакта)

- В контракте есть операция загрузки реестра и операция получения отчёта проверки.
- Модель строки содержит все обязательные поля из `AS-01`.
- Для каждой проверки `CHK-03…CHK-07` есть явный признак отказа и код причины.
- Состояния реестра и строки совпадают с описанными; новых статусов нет.
