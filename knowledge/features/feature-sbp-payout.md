# Ф2. Выплата по СБП

## Цель

Выплатить проверенные строки реестра через СБП: одной командой, с контролем статуса
самозанятого и предсказуемой обработкой ошибок. Источник фичи: `Описание продукта`
(«фичи на выбор» — «выплата по СБП»).

## Пользователь

Бухгалтер компании (запуск и разбор ошибок); исполнитель-самозанятый (получатель).

## Сценарий

1. Бухгалтер запускает выплату по реестру в статусе «Проверен».
2. Проверяются: статус самозанятого в ФНС (`CHK-08`), состояние реестра (`CHK-09`),
   средства (`CHK-10`), отсутствие активной выплаты (`CHK-11`), суточный лимит (`CHK-12`).
3. Строки отправляются в СБП; каждая строка обрабатывается независимо (`AS-06`).
4. Результат по строке: «Выплачена» либо «Ошибка» с причиной; при технической ошибке —
   ретраи 1 / 5 / 15 минут, затем DLQ (`AS-17`).
5. Реестр закрывается в «Завершён» или «Завершён с ошибками»; бухгалтер видит отчёт.

Чек ФНС — обязательное следствие выплаты по продукту (`O-05`, `AS-07`), но **отдельной
фичей не выделяется**: в состав Ф2 как самостоятельная возможность не входит.

## Результат

Выплаты исполнены или помечены ошибками с причиной, повторные переводы исключены,
реестр закрыт с отчётом для бухгалтера.

## Применимые правила

`O-01`, `O-02`, `O-04`, `CHK-08…CHK-12`; статусы
[[02-business-rules#4.3. Выплата]]; допущения `AS-05`, `AS-06`, `AS-11`, `AS-12`, `AS-13`,
`AS-17`.

## Критерии приёмки (для проверки артефакта)

- Есть операция запуска пакетной выплаты и операция получения статуса по строке.
- Идемпотентность выражена ключом `registry_id + row_id`, а не соглашением «не повторять».
- Поведение при отказе СБП и при исчерпании ретраев описано явно (`AS-17`).
- Ни в одном месте не допускается выплата без подтверждённого статуса самозанятого
  (`O-02`, `CHK-08`).
- Частичное исполнение реестра выражено явно, а не подразумевается (`AS-06`).
