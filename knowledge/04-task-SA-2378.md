# Постановка задачи SA-2378

**Источник:** Jira `SA-2378` «Настроить ИИ-агента для генерации и проверки артефактов СА»,
тип «Задача», исполнитель Антипин Дмитрий, статус «В работе».
Это постановка учебной задачи, а не требование к продукту — продуктовые факты живут в
[[01-glossary]], [[02-business-rules]] и [[03-assumptions]].

## Продукт и фичи

Выбран **ВыплатыПро** — массовые выплаты самозанятым (`Задание п. 8`).
Фичи в работе: [[feature-registry-check|Ф1. Загрузка и проверка реестра выплат]] и
[[feature-sbp-payout|Ф2. Выплата по СБП]].

## Что нужно сделать

Создать навыки для ИИ-агента, который по требованиям из Jira готовит артефакты системного
анализа. Ментор назначил **все четыре** типа артефактов из таблицы ниже. Агент берёт
требования из Jira и `knowledge` и выкладывает результат в публичный репозиторий GitHub
(`Antipindima1/722`) через Pull Request.

## Порядок выполнения (из постановки)

1. Получить у ментора тип артефакта — назначены все четыре.
2. Подготовить окружение: публичный репозиторий, агент с MCP, подключённые MCP Jira и
   MCP GitHub — выполнено.
3. Завести требования в Jira на доске Scrum: на каждую фичу карточка «Задача» и две
   «История» с критериями приёмки, связанные `relates to` — **не выполнено**, см. ниже.
4. Собрать базу знаний в Obsidian — выполнено (этот vault).
5. Написать `AGENTS.md` — выполнено.
6. Создать `skills/<название>/SKILL.md` — выполнено: пять навыков под артефакты плюс
   «Смотрящий».
7. Применить навыки к первой фиче и открыть PR.
8. Проверить результат инструментом, сохранить отчёт в `artifacts/<артефакт>-check.md`,
   сверить с user story и бизнес-правилами, оставить замечания в PR.
9. Правки вносить в навык, а не только в артефакт; каждую ошибку писать в `ai-log.md`.
10. Применить навык ко второй фиче — ошибки не должны повториться.
11. Сдать: ссылки на репозиторий и PR приложить к задаче, перевести в Review.

## Таблица выбора артефакта (из постановки)

| Слабая зона | Артефакт | Чем проверить |
|---|---|---|
| System design | C4, уровень 2 (контейнеры) | рендер в PlantUML C4 или Structurizr, аргументация решений |
| Интеграции, синхронные | OpenAPI + Sequence с ошибками и ретраями | Spectral |
| Интеграции, асинхронные | AsyncAPI | AsyncAPI CLI validate |
| Данные | ER + DDL PostgreSQL | DDL выполняется в DBeaver без ошибок |

**Статус выбора:** ментор назначил все четыре артефакта. В Jira `SA-2378` это назначение
не зафиксировано (0 комментариев на 2026-11-17) — до публикации остаётся подтверждённым
только перепиской, см. [AGENTS.md](../AGENTS.md) §2.

## Definition of Done (из постановки)

- Репозиторий публичный; в нём есть `knowledge`, `AGENTS.md`, `skills/<название>/SKILL.md`,
  `artifacts` (с `<артефакт>-check.md`) и `ai-log.md`.
- Агент получил требования из Jira и создал PR через MCP; в истории PR видно, где черновик
  агента, а где правки студента.
- Артефакт проходит проверку инструментом без ошибок.
- Каждая user story отражена в артефакте; нет элементов, не следующих из требований.
- В `ai-log.md` не меньше 5 ошибок агента по сути, минимум 2 привели к правке `SKILL.md`.
- Навык применён к двум фичам, во второй ошибки не повторяются.
- Нет токенов, данных под NDA и персональных данных.
- Ссылка на репозиторий и PR приложена к задаче.
