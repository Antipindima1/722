# Постановка задачи SA-2378

**Источник:** Jira `SA-2378` «Настроить ИИ-агента для генерации и проверки артефактов СА`,
тип «Задача», исполнитель Антипин Дмитрий, статус «К выполнению».
Это постановка учебной задачи, а не требование к продукту — продуктовые факты живут в
[[01-glossary]], [[02-business-rules]] и [[03-assumptions]].

## Что нужно сделать

Создать skill для ИИ-агента, который по требованиям из Jira готовит один тип артефакта
системного анализа. Тип артефакта назначает ментор под зону роста. Skill применяется к
фиче продукта, результат проверяется и доводится до рабочего качества. Агент берёт
требования из Jira и выкладывает результат в публичный репозиторий GitHub через Pull
Request.

## Порядок выполнения (из постановки)

1. Получить у ментора тип артефакта (например, C4 уровня 2 или OpenAPI).
2. Подготовить окружение: публичный репозиторий, ИИ-агент с MCP и skills, подключённые
   MCP Jira и MCP GitHub.
3. Завести требования в Jira: на каждую фичу карточка «Задача», к ней две карточки
   «История» (user story с критериями приёмки), связанные через `relates to`.
4. Собрать базу знаний (глоссарий, бизнес-правила, допущения) — выполнено, см.
   [[00-index]].
5. Написать инструкцию агенту `AGENTS.md`.
6. Создать `skills/<название>/SKILL.md`: когда применять, что взять на вход, шаги
   работы, формат результата, чек-лист самопроверки перед PR, чего делать нельзя.
7. Применить skill к первой фиче: агент читает карточки «История» через MCP и открывает
   Pull Request.
8. Проверить результат: прогнать артефакт инструментом из таблицы, сохранить результат
   самопроверки и прогона в `artifacts/<артефакт>-check.md`, сверить с user story и
   бизнес-правилами, оставить замечания комментариями в PR.
9. Исправлять **skill**, а не только артефакт: каждую ошибку агента писать в `ai-log.md`
   (что сделал не так, какое правило нарушено, как исправлено, что поменялось в `SKILL.md`
   или `knowledge`), затем перезапустить skill.
10. Применить доработанный skill ко второй фиче — ошибки не должны повториться.
11. Сдать работу: ссылку на публичный репозиторий и оба PR приложить к задаче и перевести
    её в Review.

## Таблица выбора артефакта (из постановки)

| Слабая зона | Артефакт | Чем проверить |
|---|---|---|
| System design | C4, уровень 2 (контейнеры) | рендер в PlantUML C4 или Structurizr, аргументация решений |
| Интеграции, синхронные | OpenAPI + Sequence с ошибками и ретраями | Spectral |
| Интеграции, асинхронные | AsyncAPI | AsyncAPI CLI validate |
| Данные | ER + DDL PostgreSQL | DDL выполняется в DBeaver без ошибок |

**Статус выбора:** ментор назначил **все четыре** типа артефактов из таблицы выше, то есть
работа идёт не по одному, а по всем направлениям. Под них в репозитории заведены навыки:
`skills/c4-container-diagram`, `skills/openapi-design` + `skills/sequence-diagram`,
`skills/asyncapi-design`, `skills/erd-data-model`. Назначение получено от ментора; в Jira
`SA-2378` на 2026-11-16 комментария с ним нет, поэтому до публикации в задаче это решение
подтверждено только перепиской (см. [AGENTS.md](../AGENTS.md) §2).

## Definition of Done (из постановки)

- Репозиторий на GitHub публичный; в нём есть `knowledge`, `AGENTS.md`,
  `skills/<название>/SKILL.md`, `artifacts` (вместе с `<артефакт>-check.md`) и `ai-log.md`.
- Агент получил требования из Jira и создал PR через MCP; в истории PR видно, где черновик
  агента, а где правки студента.
- Артефакт проходит проверку инструментом из таблицы без ошибок.
- Каждая user story отражена в артефакте, и в артефакте нет элементов, не следующих из
  требований.
- В `ai-log.md` не меньше 5 ошибок агента по сути, минимум 2 из них привели к правке
  `SKILL.md`.
- Skill применён к двум фичам, во второй фиче исправленные ошибки не повторяются.
- В публичном репозитории нет токенов, данных под NDA и персональных данных.
- Ссылка на репозиторий и PR приложена к задаче.

## Ограничения

- Работать только со своими карточками с меткой `ai-skill-<фамилия>` на доске Scrum.
- Репозиторий публичный: без токенов, данных под NDA, персональных данных и сведений с
  текущей работы.
